# 智慧治理终端与模型配置

桌面现有空间与事件功能位于「可视化事件处理工作台」，新页面「智慧治理终端」负责办结档案、月度工作总结与治理分析。两页使用同一村庄、同一事件库。手机页面与语音交互继续沿用原有功能。

## 打开与切换

运行 `npm run dev` 后，桌面入口为 [事件工作台](http://localhost:5173/)，治理终端可直接打开 [智慧治理终端](http://localhost:5173/governance)。也可点击顶部“乡居共治”左侧叶子图标，在菜单中切换两个页面。终端沿用工作台选中的村庄；要更换实景村庄，先回工作台切换。

手机 HTTP 开发入口仍为 `http://localhost:5174/mobile`，独立 HTTPS 测试服务仍由 `npm run dev:mobile:https` 在 5175 提供。手机访问时使用电脑当前局域网 IP，不能使用手机自己的 `localhost`。共用 API 只监听电脑 `127.0.0.1:5190`，由前端同源代理访问，无需向手机开放 API 端口。既有手机证书与录音配置无需因本功能重复安装。

## 模型配置

留痕、月报、分析助手共用一个阿里云百炼文本模型，默认 `qwen-plus`。如果语音整理已经配置了北京地域的 `DASHSCOPE_API_KEY`，治理功能会自动复用；不需要再把密钥填入页面。

需要单独配置时，在项目根目录 `.env.local` 中设置以下服务端变量，模板见 `.env.example`。请在本地编辑器填写实际密钥，不要发到聊天、提交到代码库或使用 `VITE_` 前缀。

```dotenv
# 可选：不填则复用已有 DASHSCOPE_API_KEY
GOVERNANCE_API_KEY=在本地填写百炼密钥
GOVERNANCE_MODEL=qwen-plus
GOVERNANCE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

读取顺序如下：

| 配置 | 优先顺序 |
| --- | --- |
| API Key | `GOVERNANCE_API_KEY` → `DASHSCOPE_API_KEY` |
| 模型 | `GOVERNANCE_MODEL` → `qwen-plus` |
| 兼容接口地址 | `GOVERNANCE_BASE_URL` → `DASHSCOPE_BASE_URL` → 北京兼容接口默认地址 |

模型与接口地址需要匹配当前百炼地域和账号权限。更换模型时，应确认它支持兼容接口的文本对话及 JSON Object 输出，并按下文流程检查实际生成结果。[百炼结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

保存后重启 API 进程即可。API 单独运行时停止原进程，再执行 `npm run dev:api`；如果使用 `npm run dev` 统一启动，可停止并重新运行该命令。不要在 5190 已占用时再启动第二个 API。前端、手机 HTTPS 与证书无需因密钥变化重新配置。

终端显示模型未连接时，办结原始事件仍照常保存，页面会明确提示。连接后重试失败留痕；模型请求失败、超时或无法解析时，不会以模板冒充已生成的汇报。`GET /api/governance/config` 仅返回是否配置、供应商与模型名称，不返回密钥；“已配置”不等于供应商鉴权或额度已通过，需以实际生成结果确认。

## 从办结到月报

1. 在工作台打开事件，受理并填写真实处理说明，再确认办结。事件同步到 API 后，服务端接收办结事实并持久化任务，生成在后台排队执行，不阻塞事件界面等待模型全文。
2. 打开治理终端，选择对应月份。「办结工作留痕」显示待生成、整理中、已留痕或生成失败。留痕围绕“问题受理、实际流转与处理、已记录结果”写成一段文字。没有提供具体措施或复核结果时，模型应简短说明当前材料范围，不能把状态“已办结”扩写成“验收合格”或“群众满意”；照片、签字、身份等字段未发送给模型，不等于原事件中没有这些资料。
3. 展开「原始办理流程」核对摘要材料，点击「查看原事件」回到工作台核对完整记录。档案保留源事件 ID、源版本、使用模型与生成时间；单条生成失败可以点击重试。
4. 该村该月待生成任务处理完成后，系统自动汇总已有有效留痕，形成月度工作总结。部分留痕失败时，月报只汇总已完成的留痕，页面同时显示待生成或需重试的数量，不能将部分资料当作全量叙述。
5. 「生成月报」「更新月报」或失败后的「重试生成」可提交任务。相同数据的有效结果会复用，重复点击不反复消耗模型调用。数据变化时会标记待更新并按新证据生成；核对完成后可复制全文或下载 `.txt` 文本。复制受浏览器权限限制时可使用下载。

月报由两部分组成：服务端根据权威事实确定生成统计段，文本模型根据当前已生成且未撤回的已办结留痕，撰写处置措施、已记录结果与通用改进建议。模型不接收未办结事件明细，不负责改算汇总数量或判断单条事项当前待办状态；动态待办分析应使用治理分析助手。服务端核对模型回显的统计值，并拒绝模型定性段中重复汇总数量、比例或动态待办状态等不符合任务边界的输出。校验失败显示错误，可手动重试；这些检查不能保证完全消除模型错误，仍需核对原事件。

有旧月报时，重新生成期间保留旧正文、原生成时间及其原来源 ID，并标记待更新。新正文与来源清单在同一次成功保存中替换；失败不会把旧正文错误地配上新来源。复制和下载同样保留 AI 整理稿说明与待更新提示。

同一事项重新受理后，旧留痕保留为历史档案并标注已重新打开，不再纳入有效月报；已有月报标记待更新。重新办结按新的有效办结时间形成新办理周期。仅补充一条仍为已办结的说明，不会另算一次办结；材料变更会使对应摘要重新整理。生成过程中若源材料已变化，服务端丢弃过时结果，避免晚返回的旧汇报覆盖新状态。

服务端重启时会恢复持久化队列；中断时仍为生成中的任务回到待处理。供应商错误不会无限自动重试，修正配置后使用重试入口。失败只影响模型整理，不撤销已经保存的事件。

## 统计与地点分析口径

| 页面数据 | 口径 |
| --- | --- |
| 本月上报 | `createdAt` 落在所选月份，按 Asia/Shanghai 计算 |
| 本月办结 | 当前仍为已办结，且办理历史有可信的本次办结时间，落在所选月份 |
| 当前待处理 / 正在办理 | 当前村庄现时状态，包含往月事件，与月度新增量不可直接相减 |
| 平均办结耗时 | 本月有效办结事项，从最初上报到本次办结的小时数；没有样本时显示暂无样本 |
| 类别与集中地点 | 所选月上报事项的原始类别与已填写地点名称；不擅自把相近名称合并 |

办结时间来自办理历史中的状态转换，不用 `updatedAt` 冒充。缺少可信办结历史、日期异常或未来日期的资料会按规则排除，并在「统计范围与数据说明」解释。

事件归属优先使用二维投影锚点的 `modelId`，其次使用三维锚点。历史无锚点记录兼容原工作台规则，可能同时出现在青禾 Demo 与既有八卦村范围中，终端会提示来源需核实；不能将这类历史数据直接视为真实村庄成效，也不能把两个页面的统计相加去重。

“事件集中地点”表示本平台登记的上报较集中，不等同于真实事故率、事故原因或未来风险预测。本系统没有完整事故台账、曝光量、人口基数或测绘配准；不使用当前模型坐标做 GPS 聚类。少量样本应明确不能证明长期规律，现场核查与后续措施仍由工作人员判断。

“村内选点”“村内”“未知地点”“未注明地点”等是泛称或缺失位置，不代表同一实际地点。即使文字标签相同，也不能将其中的记录合并判断为某个物理事故多发点，或据此安排针对该点的巡检；应先回到事件补充和核实位置。紧急程度 `high` 是人工上报标记，不是专业风险评估，不应自动改称“高风险事故”。

## 村庄治理分析助手

助手平时收起，只显示终端的机器人图标。点击后打开侧栏，可使用预设问题或直接提问，例如“本月哪些地点的事件较集中，请给出依据”或“针对尚未办结事项，建议怎样安排下一步工作”。

服务端每次按当前村庄和月份重新读取权威统计、相关事件与有效留痕，再提交给模型。回答区分分析与可执行建议；引用的事件可点击返回原记录。「数据范围与判断边界」默认折叠，可展开核对局限。没有足够依据时应说明不能判断，建议不能写成已经实施的工作。

当前实现为只读文本分析，没有联网搜索、任意工具执行、自动派单或变更事件权限。用户问题与事件材料中的指令不应改变助手任务。对话只保留在当前页面会话，重新打开同一页面可继续，切换村庄或月份、离开终端、刷新或点击「新对话」会重新开始。生成中可以取消；失败会保留问题以便再次发送。取消聊天不撤销独立运行的办结留痕或月报任务。

模型并非总能正确推理。引用可追溯、JSON 校验和 ID 过滤只能限制输出形态及来源范围，不能保证正文事实完全准确。实际汇报前应逐条核对原始事件，尤其是原因、处置措施、验收、资金和后续成效。

## 数据与实现边界

原始事件和照片仍保存在 `.local-data/issues.json`，治理档案与月报保存在 `.local-data/governance.json`，实景底图仍在 `.local-data/maps/`。请整体保留 `.local-data/`，不要为了重试模型而删除事件库。治理存储采用本地文件与写入队列，当前演示没有正式登录、分级权限或多机数据库事务；上线前需要补充服务端身份、授权、审计与备份。

模型输入保留必要的事件 ID、标题、地点文字、分类、状态、日期、处理备注与统计，移除照片、居民身份字段和原始空间坐标；已知上报人、身份标识、操作人以及手机号、邮箱、证件号等文字按规则处理。自由文本可能仍带有尚未识别的个人信息，因此不要宣称绝对匿名。

当前上下文有明确上限：助手相关事件明细最多 50 条；事件描述最多 600 字；办理历史最多保留最初 2 条与最近 10 条，每条备注最多 240 字。月报与助手最多接收最近 50 份有效留痕，每份正文最多 1600 字；助手地点最多取上报量最高的 20 个，每处最多 20 个证据 ID。月报只使用其中的已办结留痕、统计校验数据及范围说明，不附未办结事件明细。统计仍按全部符合范围的记录计算，截断与样本范围同时传给模型并在页面说明；不能声称模型逐一审阅了未提供的资料。

主要文件：

| 文件 | 职责 |
| --- | --- |
| `src/components/layout/Header.tsx` | 桌面页面切换菜单 |
| `src/components/governance-terminal/` | 档案、月报、统计、助手与读取轮询 |
| `src/services/governanceService.ts` | 浏览器同源接口与响应检查 |
| `src/types/governance.ts` | 统计、档案、月报与分析回答类型 |
| `shared/governanceFacts.mjs` | 村庄归属、上海日期、办结周期、统计及脱敏证据 |
| `server/governance.mjs` | 持久化、排队、版本检查、模型调用与治理 API |
| `server/governancePrompts.mjs` | 三个独立预设提示词与提示词版本 |

模型通过兼容接口 `/chat/completions` 调用，关闭思考模式，使用较低温度与 JSON Object 响应，服务端继续检查可用正文、字段及来源范围。JSON 模式不意味着内容真实。单条留痕提示词版本 `GOVERNANCE_PROMPT_VERSION` 当前为 `2026-10-22.2`；月报使用独立的 `REPORT_PROMPT_VERSION`，当前为 `2026-10-22.monthly.3`。仅调优月报时提升月报版本，使旧月报重新核对生成，而不使所有单条留痕无谓重算。后续调整应保持材料范围、不能虚构、村庄及证据约束，并运行相应回归测试。

| 接口 | 用途 |
| --- | --- |
| `GET /api/governance/config` | 返回不含密钥的配置状态 |
| `GET /api/governance?modelId=…&month=YYYY-MM` | 当前村庄与月份的档案、月报和事实概览 |
| `POST /api/governance/records/:id/retry`，JSON `{}` | 重新排队失败的有效留痕 |
| `POST /api/governance/monthly`，JSON `{modelId, month}` | 生成或更新月报任务 |
| `POST /api/governance/chat`，JSON `{modelId, month, question, history}` | 只读治理分析 |

POST 接口使用 JSON，同源校验并限制请求频率与体积。浏览器问题框最多 1000 字；接口问题最多 2000 字，历史最多 8 条、每条最多 3000 字。服务端模型调用有超时及并发限制；原始供应商报错和密钥不会直接展示给用户。接口返回已排队不等于生成成功，应以之后读取的任务状态为准。

助手方案参考官方 Dify 的证据前置、assistant-ui 的来源展示与状态表达，沿用项目现有 React 与 Node，没有安装额外助手框架。链接和具体借鉴点见 [治理助手实现参考](治理助手实现参考.md)。

## 功能验收顺序

以下是可重复的人工验收流程，不表示这些步骤已经全部通过；本轮实际结果由交付时的验证记录说明。

1. 在当前真实村庄创建一条明确标注为测试的事项，填写地点与描述，先受理并添加真实的测试处理备注，再办结。核对工作台、手机进度和 API 同步状态。
2. 点击叶子菜单进入治理终端，检查村名与工作台一致，找到该事项的办结档案，等待或重试生成；逐句核对模型汇报是否仅采用已填写内容，查看原始流程与原事件回链。
3. 等待月报完成，确认来源清单包含有效留痕，复制或下载文本，检查村名、月份、模型、生成时间与待更新提示。不要用未核对的演示内容作为正式工作汇报。
4. 返回原事件重新受理，再进入终端，检查旧档案撤回、有效办结统计更新、旧月报失效；重新办结后应出现新周期留痕。补充说明而不改变状态不应新增一次办结数。
5. 打开机器人助手，询问集中地点与下一步建议；点击证据返回工作台，核对数量与地点文字。换月份或村庄后，不应继续显示上一个范围的回答；样本少、没有数据或含历史兼容记录时应说明局限。
6. 测试不含任何资料的月份、模型未配置、错误密钥、供应商超时、生成期间重新受理、取消聊天、长标题与长备注。状态与恢复路径应清楚，不显示虚构成功。
7. 刷新页面和重启 API，核对档案与月报仍可恢复。使用键盘打开叶子菜单、切换选项并退出；助手应限制焦点在对话框内，Escape 关闭后回到触发入口。
8. 回归手机首页、实景底图、选点、草稿、文字上报、办理进度，以及已配置 HTTPS 下的长按录音；本次不调整手机 UI 或证书。

开发回归命令为 `npm test`、`npm run lint`、`npm run build`。涉及模型结果的自动测试应使用模拟响应验证任务与范围规则；真实百炼鉴权、额度和中文汇报质量需要实际请求及人工核对，不能以模拟测试代替。
