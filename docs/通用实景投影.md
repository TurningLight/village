# 通用实景投影

在「实景模型」中导入完整 GLB、glTF ZIP 或文件夹，切换「2D地图」或「分屏」即可查看带原模型纹理的俯视底图。新模型无需配置建筑数量、轮廓或事件范围，首次载入自动生成；刷新恢复缓存，右侧刷新按钮可重新生成。底图按模型标识分别持久化到 IndexedDB，不设过期时间，也不再按村庄数量自动淘汰。成功后显示「已保存本地，下次直接打开」；如存储失败会明确提示，并可只重试保存，无需重新生成。

## 本地模型的严格正交流程

1. 复用三维视图已加载的完整场景树、材质、纹理和对象变换。glTF 标准 Y-up 转为平台 Z-up，统一平移和等比缩放；不改变相对位置、形状、方向和比例，不抽样或替换建筑。
2. 通过 Three.js `Box3.setFromObject` 计算整棵场景树的世界边界，不使用事件点或当前镜头可见范围。按完整 X/Y 范围四边增加 3.5% 留白，自动确定图像长宽比。
3. 正交相机沿 Z 轴垂直向下，X 向右、Y 向上。相机置于全部几何最高点上方，近远裁面包含完整高度范围；顶面位置不随建筑高度改变。不使用透视截图冒充正交投影。
4. 使用原模型全部可见网格，保留纹理、深度遮挡和材质。HDR 离屏渲染后经 Three.js OutputPass 转换为显示颜色，读取像素并翻转 Y 轴，编码最长边 2048 像素 PNG。不会改动主视图镜头、灯光或模型数据，也不另开 WebGL 上下文。
5. 底图与事件共享同一世界坐标到图像 UV 的变换：`u=(x-minX)/(maxX-minX)`，`v=(maxY-y)/(maxY-minY)`。新事件直接使用三维命中的 `sceneAnchor`，避免历史相对位置误差。旧演示点保留原参考相机转换，仅作演示。
6. 将图像 UV 与事件 UV 一起映射至居中的等比显示平面，叠加到 MapLibre。该平面不受原模型坐标原点和单位影响，不充当测绘经纬度。全村按钮只以完整模型底图范围取景，不按事件裁剪。WebGL 地图失败时，SVG 回退仍显示同一 PNG 与同一事件投影。

同一场景中的所有可见建筑均参与渲染，原有数量与平面分布得以保留。建筑如果被树冠、其他建筑或悬空结构从正上方遮挡，仍遵循真实深度遮挡；程序不会虚构被遮挡区域。照片建模常把许多建筑合成单个网格，因此网格数不等于建筑数，界面不会据此生成建筑统计。

## Sketchfab 在线模型

公开 Viewer API 不提供严格正交相机，也不提供可用于本地正交渲染的原始模型。系统使用独立嵌入视图，通过官方 API 解除相机约束、根据整模边界居中，然后设置 5° 小视角及接近垂直的俯视位置（2° 倾角避免在线相机的极点限制）。必须连续校验相机位置和视角稳定后才截图：`setCameraLookAt` 的回调只确认移动开始，直接截图可能截到旧镜头并遗漏建筑。

通过八个不同高度的三维采样点及官方 `getWorldToScreenCoordinates` 校准实际三维到图像的投影矩阵，处理建筑高度和相机方向对事件点的影响；超过校准误差阈值就报错，不输出未经校准的底图。调用官方 `getScreenShot` 生成 2048×2048 PNG，结束或取消时释放独立视图。不会下载、逆向提取在线网格。

在线结果明确标为「近似平面影像」。严格保持建筑的平面形状、尺度和距离应上传原始完整本地模型；在线小视角透视仍会存在高度视差。在线加载、模型过大、相机无法稳定或网络失败时显示错误和重试入口，不降级成虚构建筑。八卦村保留作者及 CC BY-NC 4.0 署名。

## 现实精度与边界

- 保真对象是输入实景模型；模型缺失、漏建、倾斜或错位不会被投影自动修复。glTF 模型应按标准正确设置竖直方向。
- 二维影像是模型的俯视表面投影，效果取决于原始纹理和几何质量；无纹理模型不会凭空产生卫星照片。
- 未提供控制点、坐标参考系和地理变换时不能宣称真实经纬度、正北或测绘精度。方向箭头表示模型方向，实景地图不显示米制比例尺。
- 当前不自动分割建筑、不统计真实建筑数量。核实与现实完全一致，需要完整实景源数据及实测参照。
- 2048 像素底图是浏览器内的交互预览，放大后不会增加原图细节；大范围高精度交付可后续扩展分块正射渲染和瓦片。

## 验证

`npm test` 包含完整边界、27 栋分散及旋转建筑、边缘高楼、大坐标、图像比例、世界坐标与显示平面转换、在线透视矩阵校准、事件锚点与相机无关、缓存隔离和淘汰、相机移动结束等待及取消测试。

浏览器检查 GLB、带纹理 glTF ZIP 自动投影、替换及刷新缓存、三维屋顶选点新增事件与二维屋顶对应、缩放至全村，以及八卦村在线模型的俯视影像。测试模型见 `tests/fixtures/models/`。


## 初始化与本地恢复（2026-10-22）

- 启动时先读取 IndexedDB 中的 PNG、模型边界和坐标变换，已有有效底图直接显示，不调用投影生成接口。保留既有版本 2 数据，无需重新生成。
- 桌面现在默认 3D 主视窗与左下角二维小地图，点击小地图可展开左右对照。进入纯二维视图时，有缓存就只加载二维地图，不启动在线 iframe 或本地三维渲染器。切回三维时才载入三维模型；一旦载入则保留镜头状态。
- 在线村庄首次生成不依赖主三维视图的 viewerready，因此二维模式只需载入一个投影用模型。主视图稍后加载完成不会取消或重启正在运行的投影任务。
- 使用与底图分辨率匹配的 2048 纹理上限；相机定位与纹理加载并行，取消原有额外 12 秒纹理等待。viewerready 已保证基础纹理；对后续高清更新使用短暂静默检测，额外等待上限为 2.5 秒，不依赖最后一次纹理完成事件。
- 相机、投影校准及影像接口均有单独的超时和取消处理，进度文字按实际阶段更新。八个坐标采样并行获取。完整几何范围和相机稳定校验保持不变。
- 手动重新生成只强制一次，之后刷新、切换场景或返回该村庄继续使用已经提交的底图。只有成功生成后才覆盖该模型的旧缓存，失败不会删除原缓存。
- 尝试申请浏览器持久存储；浏览器拒绝该申请不影响已成功保存的 IndexedDB 数据。缓存属于当前浏览器和网站来源（协议、主机、端口），跨端口、无痕窗口和清除站点数据不共享。使用固定网址打开项目可持续复用。

## 手机共享与同步（2026-10-22）

电脑自动向共用 API 发布当前真实模型的描述、投影元数据和 PNG，服务端持久化于 `.local-data/maps/`；浏览器 IndexedDB 仍作为电脑本地投影缓存。手机按 `activeRealModelId` 每 2.5 秒检查实景选择及投影更新，只下载二维影像，不加载原模型。电脑换村时先同步标识，新投影未就绪时显示等待；切回 Demo 不改变手机最后选择的真实村庄。

手机选点保存原图 UV、投影版本与对应三维射线，不能由一张二维图推断地面高度。电脑三维视图以真实网格拾取显示该射线命中位置；未命中时不生成假点。投影更新后，旧记录只有可靠三维锚点才能重新投影；其余旧版位置保留列表记录并提示重新定位，不在新底图上猜测位置。详见 [手机实景底图与录入](手机实景底图与录入.md)。
