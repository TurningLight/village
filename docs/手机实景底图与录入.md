# 手机实景底图与录入

手机直接使用电脑当前真实村庄 3D 模型生成的二维投影。它显示同一份带纹理的 PNG 和校准信息，不在手机重新加载或渲染 3D，也不再提供青禾村 Demo 或手动选村。

## 运行与入口

```sh
npm run dev
```

这会启动桌面5173、手机HTTP5174与共用API5190。真机录音继续使用现有证书，另行启动：

```sh
npm run dev:mobile:https
```

| 使用场景 | 地址 |
| --- | --- |
| 电脑管理端 | `http://localhost:5173/` |
| 电脑浏览手机界面 | `http://localhost:5174/mobile` |
| 手机 HTTPS | `https://电脑当前局域网IP:5175/mobile` |

当前已测试的热点地址为 `https://10.142.176.9:5175/mobile`；IP 改变后使用新地址，并更新包含该 IP 的服务证书。手机不能用 `localhost` 指向电脑。用户已确认 vivo 手机 HTTPS 和录音可用，本轮沿用 `.env.local`、证书和手机信任配置；Key 不进入手机代码。详见 [语音配置与手机HTTPS测试](语音配置与手机HTTPS测试.md)。

## 电脑与手机如何联动

1. 在电脑选择「实景模型」，打开在线模型或已上传的本地模型。桌面默认 3D 主视窗与左下二维小地图，点击小地图可展开左右对照。
2. 电脑自动共享村庄标识、名称，以及已生成的二维 PNG 和投影校准信息。已有缓存直接共享；首次模型等待生成。同步失败时可在电脑提示处重试。
3. 手机读取共享目录，顶部显示同一真实村名。它每 2.5 秒检查一次变化，实际显示时间还取决于请求和图像传输。
4. 电脑更换真实模型，手机自动切换到新村庄的事件、底图和草稿。新村庄暂时没有投影时显示等待，不使用上一村庄的图像。电脑切回青禾村 Demo 时，手机继续使用最后的真实村庄。
5. 电脑重新生成同一模型投影，手机收到新版本后更新图像。正在录入的文字仍保留，位置需要在新图上重新确认。

从未共享过真实村庄时，手机显示「等待电脑端实景村庄」。同一村庄未生成底图时，页面可说明等待原因；有效选点和提交需要该村庄的当前投影。手机页面无需保持电脑的三维渲染器运行，但共用 API 必须运行才能同步和提交。

## 用手机上报

首页的「看看村里的实景地图」进入底图与办理进度；「随手报」打开原有上报表单。填写问题、具体位置文字与照片后，点击地图选点入口：

- 单指拖动，双指缩放；右侧控件可放大、缩小、显示完整地图。
- 轻点影像标记位置，或用中心选点控件，再按「使用这个位置」。拖动、双指缩放及点击影像外留白不会落点。
- 核对村名、标记与描述后提交。成功回执以服务器持久化确认为准，之后电脑在相同村庄中可查看和办理。
- 电脑在录入中切换村庄，原村草稿按模型 ID 单独保存，再打开新村庄的表单。不要把原村的问题填到新村表单中；切回原村可继续草稿。

长按语音、松开转写、整理填写与照片功能保持现有流程。语音不会自动选择地图位置或直接提交。

## 位置的含义

手机保存 `projectionAnchor`：模型 ID、投影生成时间、原图 UV，以及由校准变换反算的三维射线。UV 是图像内部的相对坐标，不受手机平移、缩放、屏幕大小或留白影响。系统不从二维像素猜测建筑高度，也不把它当作真实 GPS。

电脑三维视图通过真实网格拾取射线，命中后才显示对应三维标记；未命中不生成假点。已有可靠 `sceneAnchor` 的事件可以重新投影。仅有旧版二维锚点的事件在投影更新后，不能保证继续套用旧 UV：当前地图会提示需要重新定位并隐藏这些旧版点，记录仍可在事件列表查看。

保真依据是输入模型本身。遮挡、缺失建筑、纹理质量，以及在线模型的近似俯视透视等限制，仍见 [通用实景投影](通用实景投影.md)；本功能没有新增建筑分割、GPS 配准或测绘精度承诺。

## 本地持久化与接口

电脑原有 IndexedDB 投影缓存保留。共用服务另行保存 `.local-data/maps/catalog.json` 和内容版本化的 PNG，重启服务后继续读取；手机首次打开只需获取已共享目录与图像。图像地址含内容版本并使用长期缓存。手机目录缓存不能代替完整离线应用，也不能在 API 断开时确认新上报成功。

| 接口 | 作用 |
| --- | --- |
| `GET /api/maps` | 当前村庄目录、`activeModelId`、`activeRealModelId` 与投影元数据 |
| `PUT /api/maps/:modelId` | 电脑发布模型描述、校准元数据及 PNG；发布图片本身不改变当前村庄 |
| `PUT /api/maps/active` | 电脑选择当前模型；选择真实模型更新 `activeRealModelId`，选择 Demo 保留它 |
| `GET /api/maps/images/:revision.png` | 获取内容版本固定的共享 PNG |
| `POST /api/issues/report` | 手机提交上报，服务端核对当前真实村庄与投影版本后保存 |

提交撞上切村或投影更新时，服务器返回409：`MAP_CHANGED` 表示真实村庄已变，`MAP_PROJECTION_STALE` 表示图像版本已变，`MAP_NOT_SHARED` 表示该模型尚无可用共享投影。页面保留填写内容；同步到当前村庄后重新选点再提交。校验与保存串行处理，避免在两者之间切换底图造成错误定位。

事件和照片仍存放在 `.local-data/issues.json`。草稿以模型 ID 在当前站点 IndexedDB 中隔离；HTTP、HTTPS、不同 IP 或端口是不同站点，身份与草稿不自动互通。

## 手机验收清单

1. 电脑选择真实模型，手机顶部自动显示同一村名；首页缩略图和进度地图与电脑二维投影中的建筑分布一致。
2. 手机放大、缩小、拖动、双指缩放后选点，确认标记仍落在所选建筑或道路；取消手势和点击留白不产生标记。
3. 提交一条明确标为测试的事件，电脑相同村庄二维地图出现同一位置；受理或办结后手机状态和办理说明自动更新。
4. 录入内容后关闭、重开并刷新，确认本村草稿恢复；切换另一个真实村庄，确认底图、事件和草稿不串村。新图未生成时显示等待；电脑切 Demo 后手机仍显示最后真实村庄。
5. 电脑重新生成投影，确认手机加载新图；未提交位置需要重新确认，旧版不可靠位置不会出现在错误建筑上。
6. 暂停 API 后提交不能显示成功，重启后共享底图仍存在；文字、照片、语音与进度原有流程仍可使用。

## 后续 UniApp 接入

可继续复用模型 ID、共享目录、PNG、校准参数、`projectionAnchor` 和服务端校验接口。纯坐标函数集中于 `src/lib/projectionCoordinates.ts`，共享类型位于 `src/lib/sharedMapTypes.ts`。UniApp 需重写图片手势、标记与页面组件，并替换请求、存储、录音等平台能力；不需要为手机另造一套村庄底图。业务、录音和草稿适配边界见 [手机端开发与测试](手机端开发与测试.md)。

## 本轮验证（2026-10-22）

85 项自动测试、lint、双端 build 已通过。实际浏览器已完成真实底图选点、提交、详情查看与桌面接收同名验收事件；服务端存储的 UV 与当前投影匹配，手机新记录没有虚构三维锚点。现有 CA 信任下，HTTPS 手机入口及同源地图接口均返回200。本轮独立界面审阅结论为 ship，分屏标记错位修复已复核；详细证据与范围见 `.impeccable/review/real-map/verification.md`。
